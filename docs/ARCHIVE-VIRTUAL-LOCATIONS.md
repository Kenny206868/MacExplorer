# Editable archive locations

Archives now have a distinct `Location.archive(source, folder:)` identity. Tab history/session persistence records the archive and relative member folder; `Location.directory` remains nil. No imaginary `file:` URL is produced for an archive member. Native file mutations, clipboard, file promises and Quick Look therefore cannot accidentally act on a similarly named local object.

Select an archive and use Browse/Extract Archive to enter its virtual location. The production SwiftUI Table supports nested folders, selection, name filtering, breadcrumbs and back/forward/up navigation. The titlebar represents the real archive file; pane paths show the virtual member folder. Archive controls offer New Folder, Add Files or Folders, Rename, Remove Selected and explicit Replace Contents. Local URL drops stage an import confirmation rather than mutating immediately. Commander users can import the other pane's local selection or extract selected members to its local destination. Extraction uses the serialized file engine and its normal collision/recovery handling.

Editing rebuilds unencrypted ZIP or TAR, with TAR optionally gzip/bzip2/xz-compressed. Namespaces include implicit folders; case/Unicode aliases, file-as-parent conflicts, duplicate names, traversal, imported links and configured expansion/entry budget violations stop before installation. Encrypted archives, link/special-object archives and other formats remain read-only. Passwords are memory-only and never enter journal receipts. Reconstruction preserves supported standard member metadata, not arbitrary vendor-specific fields or archive comments; the UI explains this before edits. The original archive is retained byte-for-byte for Undo.

The engine creates an exclusive private candidate beside the archive, streams member data through libarchive, validates output paths, copies the archive file's native metadata, synchronizes the candidate and then performs two journaled exclusive moves. A single receipt checkpoint separates crash compensation from committed Undo history. No in-place truncation or unsafe overwrite fallback is used. Seven actual subprocess exit boundaries test the archive-specific install/checkpoint sequence; existing journal tests exercise interrupted compensation as well.

The native gallery contract includes archive root/folder and recovery interrupted/history states in light and dark appearances. Rendering tests assert no implicit mutation, then perform an actual journal-backed rename and exact-byte Undo. macOS CI remains the authority for AppKit/SwiftUI and native metadata behavior; Linux streaming tests do not certify those paths.

Scope boundaries: archive member desktop drag-out/file promises, arbitrary nested-archive editing and every physical provider/VoiceOver/input-device combination are not certified by these tests. Selected extraction is the supported bridge to physical files. File-provider OS outcomes, permanent deletion and unsupported filesystem flush guarantees require explicit review where certainty is unavailable. Production notarization and Sparkle signing use owner-managed credentials.
