# Dual-pane workspace design and interaction contract

The native SwiftUI interface is the product. Keep the reference light/dark palette, 48/54/54-point top chrome, fitted Details columns, restrained separators and shared sidebar. Each pane owns an independent tab group with its own locations, history, selection, queries and view options. The shared top tab strip follows the active group; each pane's title menu also selects its tabs. Focus is separate from location and selection.

An active pane uses an accent indicator, numbered badge and Active label. Inactive file names remain readable and their selections remain visible. Shared sidebar, commands, inspector, path and search follow the active pane. Both per-pane paths remain visible and independently editable. Switching focus does not refresh away selections or cancel a transfer. Narrow windows stack panes without changing preferred orientation. Auxiliary panes are withheld when dual-pane space is insufficient, while preserving user intent.

Copy to Other Pane and Move to Other Pane show the destination; moves require confirmation and identity revalidation. Cmd/Ctrl+Shift+D toggles panes; Tab switches panes only in file-surface focus. Cmd/Ctrl+Option+C copies and Cmd/Ctrl+Option+M requests a move. F5 remains Refresh. F6 cycles location/search/files. Arrows, Home/End, Page Up/Down, Shift ranges, Control focus-only, Control+Space and type-to-select share selection logic. Text editors and modal surfaces retain their keys.

Each pane receives URLs and native file promises using its own destination. Dragging from an inactive pane activates its source group before selecting transfer entries. An external reported drag mask never authorizes deletion of source files by itself. Native file promises retain their existing staged import/export, cancellation and recovery contracts.

Trackpad swipes navigate history, pinch changes icon density and ordinary scrolling stays native. Pinch accumulation is bounded and keyed to its source pane; cancellation, nonfinite values and pane changes reset it. Touch-friendly mode uses 44-point file rows, column headers and shared controls, with explicit Select/Open/actions and long press. Physical touchscreen behavior depends on supported macOS input delivered by the device/driver, not an invented iPad layer.

CI renders actual populated light/dark panes, both orientations, narrow fallback, wide inspector, touch-friendly selection and active-pane changes. Native event and filesystem tests cover command ownership and transfer snapshots. Alpha binaries and their native galleries are assembled from the same successful commit. Screenshot palette checks use explicit sRGB and do not replace visual review or hardware/assistive-technology evaluation.
